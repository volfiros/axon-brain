# Source adapters: Plane and Google Docs

Status: proposed; live integrations have not run. Revised 2026-10-09. This specification extends [Phase 2](phase_02_ingestion_and_sync.md) and shares the canonical [schema](graph_schema.md), [contracts](contracts.md), and [import protocol](phase_01_graph_and_fixtures.md#snapshot-consistency).

## Scope and common boundary

The demo requires read-only live Plane and Google Docs adapters, alongside GitHub/Git verification. Jira JSON/CSV, Markdown, and saved provider exports remain supported for setup, regressions and a visibly labeled fallback. Export-only operation is a partial deliverable and cannot pass the live-adapter demo gate. Enterprise per-user ACL synchronization and incremental webhooks remain Phase 7.

Proposed implementation files: `backend/app/connectors/{plane,google_docs}.py`, `backend/app/ingestion/{normalize,reconcile,snapshots}.py`, provider response fixtures and connector tests. Use a shared `SourceAdapter.read_scope(config) -> SourceReadResult` boundary. The result contains provider/instance/scope, mode, observation window, source version references, normalized nodes/edges, immutable document content references, explicit coverage and sanitized failures. Adapters fetch data; only the loader publishes graph changes. Credentials and native response shapes stay inside the server-side adapters.

Plane/Google Docs/GitHub records and confirmed catalog/mapping imports own STRUCTURAL. Operational receipts enter the durable incident event log and publish INCIDENT-only bounded deltas under [graph publication](graph_publication.md). Adapters assign/validate immutable owner fields; never overwrite structural instance identity/catalog fields with runtime observations or erase incident links during source reconciliation. Full recovery bundles are retained per owner.

Configuration includes an allowlisted instance/project or document scope, provider settings, schema/mapping version and credential references. Retain `FIXTURE`, `IMPORT`, or `LIVE` per source in the bundle's `SnapshotRef` entries; a live refresh cannot relabel saved exports or synthetic relationships as live provider evidence. A confirmed manifest remains manifest evidence even when its linked records were fetched live. Completion means complete within the declared scope and observation window, not a transactionally simultaneous view across providers.

Default HTTP timeout is 10 seconds per attempt, with at most two retries for transient transport failures, HTTP 429 and 5xx, inside a 60-second retry budget per operation. Honor `Retry-After` if it fits the remaining budget; otherwise return a coverage failure. Do not retry invalid input or permission/authentication failures except one Google token refresh when applicable. Follow all pagination cursors, detect repeated cursors, and mark any time/row/page limit as incomplete. Never log tokens, private raw payloads or inaccessible document text.

Prepare and persist the full reconciled bundle before entering `DIRTY`. Required-source failure aborts that live import before graph mutation. A coherent export bundle may be imported only in explicitly selected export mode. An incomplete enumeration cannot authorize removal: retain prior records with their original observations and incomplete coverage, or fail the bundle. Deletion/tombstoning requires explicit authoritative evidence. Permission loss makes the affected source/document unavailable to retrieval even while old records remain retained; do not present retained content as currently authorized.

## Persistent source-access handling

Use `SourceAccessRecord` from [contracts](contracts.md#source-access-registry) in the retained transactional local store. Key it by tenant/demo principal, provider credential scope and resource or explicit source-scope ID. Persist a known denial independently of the graph import outcome, incrementing `access_version`. Source-level restrictions cover child resources. Definitive permission denial is DENIED; ambiguous 403/404 unavailability is UNAVAILABLE and suppresses retained content without establishing deletion. Ordinary transport/rate-limit failures retain their separate freshness/coverage meaning. An unavailable registry fails closed for the affected live scope.

Check access before retrieval/model input, retained trace/audit access, and final response publication. Record both resource and enclosing-scope access versions with evidence. If those versions change during a model call, discard the prepared output and rebuild once from allowed evidence within the shared request budget, or use the content-free source-access error from contracts. Never serve the old answer merely because its graph generation is unchanged. A failed durable denial write blocks affected reads until recovery; a later successful graph import cannot clear the denial. Restore access only after a successful authorized source recheck. This is the single-demo-identity mechanism; enterprise ACL synchronization remains Phase 7.

## Plane adapter

Default settings are Plane Cloud at `https://api.plane.so`, API v1, a configured workspace slug and one project UUID, and server-only `PLANE_API_KEY` in `X-API-Key`. A self-hosted base URL must be explicitly allowlisted. Pin v1 response fixtures and record the deployment/version used; do not auto-switch to v2. Plane currently documents both versions, with different read shapes. [API authentication and pagination](https://developers.plane.so/api-reference/introduction), [version guidance](https://developers.plane.so/api-reference/v2/introduction).

Read the project's metadata, state/type definitions, and `/api/v1/workspaces/{workspace_slug}/projects/{project_id}/work-items/`; follow `next_cursor` until the provider reports no remaining pages. Use individual work-item reads where needed to resolve parents or omitted fields. Resolve only allowed parent/project scopes; inaccessible parents make hierarchy coverage partial. Retrieve all assignees. v1 work items expose native IDs, parent/state information and source timestamps. [Work-item shape](https://developers.plane.so/api-reference/issue/overview), [detail endpoint](https://developers.plane.so/api-reference/issue/get-issue-detail).

Canonical identity is `tenant:plane:<instance-key>:<workspace-id>:<project-uuid>:work-item:<uuid>`; obtain the workspace ID from authoritative metadata. Keep project identifier plus sequence number as `external_key`. Keys/titles and changed instance URLs must not merge different native identities. Map configured native epic types to `Epic`; other configured types map to `Task.work_item_type`. Require an explicit type mapping for the demo; unknown types remain validation conflicts. A module or cycle is not automatically an epic.

Use explicit `parent` IDs to create confirmed hierarchy edges after validating endpoint types. Retain raw state, priority, all assignee IDs, and `updated_at` when supplied; missing times stay unavailable. Default state-group mapping is backlog/unstarted to `TODO`, started to `IN_PROGRESS`, completed to `DONE`, cancelled to `CANCELLED`, and triage/unrecognized to `UNKNOWN`. Explicit configured state-ID overrides may establish `BLOCKED`; text or generic related-item links cannot do so. Preserve unknown assignment as `null` and known unassigned as `[]`.

For [Clef task-branch discovery](task_branch_association.md), also read paginated v1 `/api/v1/workspaces/{workspace_slug}/projects/{project_id}/work-items/{work_item_id}/activities/` and retain native old/new assignment/state values and event timestamps. Reconstruct work periods and preserve incomplete histories; current `updated_at` cannot stand in for assignment or in-progress start. Read-only GitHub/Git evidence supplies author IDs, separate author/committer timestamps, exact heads, reachable commits and bounded changed-file summaries. An explicit identity manifest maps provider users to authors; absent mapping/history disables inference for that task rather than guessing. [Plane activities](https://developers.plane.so/api-reference/issue-activity/list-issue-activities), [GitHub commits](https://docs.github.com/en/rest/commits/commits).

For this demo, the verified relationship manifest is required for dependency direction and `CODE`/`PROCESS` kind, task/repository bindings, implementation/delivery groups, revision effects, and document links. This is the default dependency adapter; native Plane dependency enumeration is not a required capability or assumed API endpoint. Provider relations may be retained as candidate evidence, but cannot replace that verified manifest without a separately tested mapping. Do not infer code completion from tracker state.

Missing pages, inaccessible parents, unsupported fields and conflicting mappings remain coverage gaps. Missing work items after a filtered/paginated read do not prove deletion or cancellation; archived/deleted semantics must be verified before tombstoning. Compare source update times during reconciliation to reject stale imports without fabricating newer times.

## Google Docs adapter

Use OAuth for the configured demo user, with server-side access/refresh tokens and the scopes `https://www.googleapis.com/auth/documents.readonly` and `https://www.googleapis.com/auth/drive.metadata.readonly`. Enable Docs and Drive APIs. Store OAuth client credentials and tokens outside fixtures/version control. Read a manifest-provided allowlist of native document IDs; do not scan the user's Drive or request write scopes. The APIs document the required read scopes. [Docs retrieval](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/get), [Drive metadata retrieval](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/get).

For each document, call Drive `files.get` with `id`, `name`, `mimeType`, `modifiedTime`, `version`, `webViewLink` and `trashed`. Require the Google Docs MIME type and a non-trashed file. Retrieve Docs `documents.get` with `includeTabsContent=true` and `suggestionsViewMode=PREVIEW_WITHOUT_SUGGESTIONS`, leaving comments omitted. Read Drive version again; if it changed, retry the complete metadata/content sequence once. A second change produces an incomplete retrieval and blocks that required live import. This detects retrieval races without claiming a cross-service transaction.

Recursively process document tabs and child tabs in source order. Preserve tab IDs/titles, heading hierarchy, paragraph text, ordered/unordered list structure, and table row/cell order. Use section anchors bound to the content version and tab ID; use provider heading IDs where available, otherwise deterministic local anchors within that version. Comments and proposed edits do not become accepted runbook instructions. Unsupported non-text content is listed in coverage/limitations; a section whose instructions depend on an unsupported image/object is not a complete procedural source.

Canonical document identity is `tenant:google-docs:document:<document-id>`. Store the retrieved title/source URL, Drive `modifiedTime` and `version`, nullable observed Docs `revisionId`, and a SHA-256 hash of deterministic normalized content. Persist the normalized content and bounded source response before graph publication; graph nodes reference immutable versioned content. Excerpts retain document ID/version/hash, tab ID and section anchor. Drive version is source metadata; content hash identifies the locally stored rendition. Docs revision IDs are temporary and cannot serve as permanent content-storage keys. [Drive version semantics](https://developers.google.com/workspace/drive/api/reference/rest/v3/files), [Docs revision semantics](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents).

The manifest supplies `DesignDoc`/`ProcessDoc` type, `CURRENT`/`SUPERSEDED`/`DRAFT` status, explicit task links and allowed scope. A title does not establish procedural currency. Preserve superseded versions for evidence, while current accessible sections alone supply default runbook guidance. A 403/404 is an unavailable record, not confirmed deletion; a known revoked document is excluded from retrieval without leaking its content. No writes, shares or comments are performed by this adapter.

## Acceptance and completion record

Connector contract checks use saved synthetic/sanitized API response fixtures. Cover Plane cursor pagination, repeated/missing pages, unknown states/types, all assignees, parent scope, duplicate display keys, old update times and missing-record reconciliation. Cover Google nested tabs, lists/tables, suggestion exclusion, anchors/hashes, unsupported content, missing bytes, trashed files and version changes across retrieval. Both adapters need timeout, rate-limit, permission and credential-failure cases with no secret exposure or silent fixture substitution.

Import a document, deny access during a subsequent preparation failure, restart, and verify retained content is suppressed from queries, traces and association audits. Repeat denial while an answer call is outstanding with unchanged graph generation. Test source-wide denial over previously allowed children, failed registry writes/reads, ambiguous 404 without tombstoning, transport timeout without a false revocation claim, and successful authorized access restoration. No model fallback may expose the invalidated content.

The live smoke gate uses a permitted real Plane project and a real allowlisted Google Doc. Retrieve their metadata/content, import the confirmed manifest links, ask for task context, and verify citations against the actual source records. Include a Google Doc with multiple tabs and a table. Confirm refresh behavior with observed source changes, without granting application write capabilities. Retain tested API/client versions, instance/project/document scope, source observation times, sanitized import report, actual citations and pass/fail results.

Missing credentials or provider availability are recorded as blocked/unevaluated live checks. Labeled export fallback remains useful, but Phase 2's live-adapter gate and Phase 6's full demo gate stay incomplete until both adapters pass. These are future checks; this document does not claim live calls or executable tests have run.
